Entrenamiento Continuo (CT)

MLOps Nivel 2: La Evolución del Modelo

Definición

Es la capacidad de un ecosistema MLOps para re-entrenar, validar y registrar automáticamente nuevos modelos en respuesta a disparadores de rendimiento o datos. El CT asegura que la inteligencia del sistema no sea estática, sino que aprenda de la **"Verdad de Campo" (Ground Truth)** capturada en producción.

El Valor del CT

"Mientras el CI/CD automatiza el software, el CT automatiza la ciencia. Es el motor que combate el Model Decay y el Concept Drift, manteniendo el ROI del modelo intacto frente a un mundo cambiante."

El CT orquestra el flujo automático desde la Fase 1 hasta la Fase 4 cuando la Fase 5 detecta una anomalía.

Detalle Técnico de la Fase CT

1. Triggers (Disparadores)

La Señal de Activación

Un pipeline de CT no corre 24/7. Se activa bajo condiciones específicas validadas estadísticamente.

Por Calendario

Cada lunes 02:00 AM para capturar la tendencia de la semana.

Por Drift

Detectado en Fase 5: La distribución de datos cambió > 15%.

Por Performance

El F1-Score real en producción cayó por debajo del 0.85.

# Lógica de Trigger en el Orquestador def check_retrain_condition(drift_score, performance_metric): if drift_score > 0.2 or performance_metric < 0.80: trigger_pipeline(project_id="CT_Sales_Forecast")
2. Auto-Retraining Pipelines

Orquestación Inmutable

El pipeline toma los datos frescos, los valida y ejecuta el entrenamiento usando los scripts de la Fase 2.

# Pipeline de CT (Conceptual KFP/Airflow) def ml_retraining_pipeline(): data = fetch_new_data_from_feature_store() validate_data_schema(data) # Calidad Innegociable # Re-entrenamiento con el modelo ganador anterior model = train_model(data, params=latest_params) # Guardar en MLflow Artifact Store log_to_registry(model, stage="Challenger")
3. Evaluación Comparativa (Champion vs Challenger)

Gatekeeper de Calidad

Nunca reemplazamos el modelo actual automáticamente. El nuevo modelo debe demostrar superioridad.

# Evaluación Champion (Producción) vs Challenger (Nuevo) def evaluate_and_promote(new_model, current_model, test_data): challenger_perf = eval(new_model, test_data) champion_perf = eval(current_model, test_data) # Promoción solo si mejora > epsilon if challenger_perf > (champion_perf + 0.02): promote_to_production(new_model) else: abort_deployment(reason="No significant improvement")

Validación Cruzada (K-Fold): El Filtro CT

Definición Industrial

En el Entrenamiento Continuo, no confiamos en un solo split. La Validación Cruzada divide los datos nuevos en $K$ bloques, entrenando y validando $K$ veces. Esto asegura que el "retrain" sea robusto a fluctuaciones estacionales en los datos frescos.

from sklearn.model_selection import cross_val_score scores = cross_val_score(model, X_new, y_new, cv=5) # ALERTA: Si std(scores) es alta, el nuevo dato es ruidoso. No desplegar.

Ventajas

  • • Máxima estabilidad estadística.
  • • Detecta Overfitting local.
  • • Evita el sesgo de selección.

Desventajas

  • • Coste computacional $K \times$.
  • • Lenta para modelos pesados.
  • • Compleja en Series Temporales.
Diferenciador: "En CT, la validación cruzada actúa como el seguro contra incendios; previene que un lote de datos corruptos re-entrenen el modelo y rompan el negocio."

Diagnóstico de Salud: CT Phase

Error: Feedback Loop Bias

Entrenar el modelo solo con los datos que "pasaron" el filtro del modelo anterior. Consecuencia: El modelo se vuelve cada vez más ciego a los casos que ya rechaza. Solución: Incluir muestras aleatorias de exploración en el entrenamiento.

Práctica: Shadow Retraining

Ejecutar el re-entrenamiento en un entorno paralelo "espejo" y comparar predicciones en tiempo real antes de mover al Champion al Registry oficial.

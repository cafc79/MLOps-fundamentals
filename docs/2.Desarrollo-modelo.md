# Model Development

MLOps Pillar #2: De Notebooks
a Pipelines

### Definición de la Fase

Es el proceso de ingeniería donde se seleccionan algoritmos, se ajustan hiperparámetros y se
validan modelos. En MLOps, el objetivo es convertir la experimentación científica en
**artefactos de software reproducibles**, auditables y escalables.

#### La Filosofía Modular

"Los notebooks son para explorar; los scripts son para producir. Model Dev en MLOps exige que el
entrenamiento sea un proceso **automatizable** y libre de estados manuales."

## Conceptos Críticos

- **Tracking de Experimentos:** Registro inmutable de cada
  intento (código, datos, métricas) para evitar el "funciona en mi máquina".
- **Optimización de Hiperparámetros:** Búsqueda sistemática
  (Bayesiana/Grid) del mejor conjunto de parámetros para el modelo.
- **Validación Progresiva:** Evaluación que trasciende el
  accuracy, enfocándose en métricas de negocio y equidad (fairness).

## Análisis de Valor

#### Ventajas Industriales

- • Trazabilidad total (del dato al modelo).
- • Reducción de sesgos mediante validación sistemática.
- • Colaboración eficiente entre científicos de datos.

#### Desventajas / Retos

- • Complejidad en la gestión de infraestructura de tracking.
- • Latencia en el desarrollo por rigor de modularización.
- • Curva de aprendizaje en herramientas de orquestación.

## Foco: Validación Cruzada (K-Fold)

### Definición y Concepto

La Validación Cruzada es la técnica estándar para evaluar cómo los resultados de un
análisis estadístico se generalizan a un conjunto de datos independiente. Divide los
datos en **$K$ subgrupos**, entrenando $K$ veces y promediando los
resultados.

Concepto Clave: Evita el sobreajuste
(Overfitting) al asegurar que el modelo sea robusto ante variaciones en el set de
entrenamiento.

### Análisis Comparativo

#### Ventajas

Usa todo el dataset para entrenamiento y
validación. Reduce el sesgo del split aleatorio único.

#### Desventajas

Coste computacional $K$ veces superior. Riesgo
de fuga de datos si el preprocesamiento no está en un Pipeline.

## Diagnóstico de Salud: Model Dev

#### Error: Data Leakage en Validación

Calcular la media/desviación de todo el dataset antes de la Validación Cruzada.
**Solución:** Usa `sklearn.pipeline.Pipeline` para que el escalador se
ajuste solo en los folds de entrenamiento.

#### Práctica: Model Cards

Generar automáticamente un documento que resuma las limitaciones, el uso previsto y las métricas
de equidad del modelo antes de registrarlo.

### Health Check Indicators

##### Reproducibilidad

¿Puedo recrear el modelo exacto con un solo script y un
commit hash?

##### Robustez

¿La varianza del performance entre folds de
Cross-Validation es < 5%?

##### Interpretabilidad

¿Sabemos cuáles son las 3 variables que más influyen en la
predicción?

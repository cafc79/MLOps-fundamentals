Data Management

MLOps Pillar #1: Datos como Código

Definición

Es la práctica de ingeniería de aplicar principios de DevOps al manejo de datos (DataOps). En MLOps, implica garantizar que los datasets sean **inmutables, versionados y validados**, eliminando la discrepancia entre el entrenamiento y la inferencia en tiempo real.

Filosofía Data-Centric AI

"El rendimiento de la IA mejora más iterando sobre la calidad de los datos que ajustando el algoritmo. Si el dato es ruidoso, el modelo será ruidoso, sin importar su complejidad."

Conceptos Clave

  • Consistencia Online/Offline: Garantizar que el modelo use las mismas transformaciones en entrenamiento que en producción.
  • Feature Store: Almacén centralizado que sirve como "fuente de verdad" para las variables predictivas.
  • Data Lineage: Trazabilidad total del origen del dato y cada transformación que sufrió hasta llegar al modelo.

Análisis de Valor

Ventajas

  • • Reproducibilidad total de experimentos históricos.
  • • Detección temprana de anomalías en el flujo de entrada.
  • • Cumplimiento normativo (GDPR/PII) simplificado.

Desventajas

  • • Alta latencia inicial por procesos de validación.
  • • Costo elevado de almacenamiento de versiones (Snapshots).
  • • Curva de aprendizaje técnica (DVC, Feature Stores).

Riesgo: Entrenamiento-Servicio (Skew)

Ocurre cuando las transformaciones de datos en producción no coinciden exactamente con las de entrenamiento. Una Feature Store es la solución técnica estándar para este problema.

Etapas del Ciclo de Vida de Datos

1. Ingesta y Conectividad

Extracción Multifuente

Desacoplamiento de fuentes mediante brokers de mensajes o conectores inmutables.

# Ejemplo: Ingesta determinista desde un Feature Store (Feast) from feast import FeatureStore store = FeatureStore(repo_path=".") training_df = store.get_historical_features( entity_df=entity_df, features=["driver_stats:acc_rate", "driver_stats:rating"] ).to_df()
2. Pipelines de Ingeniería (ETL)

Limpieza y Transformación a Escala

Uso de orquestadores para automatizar la normalización y escalado.

# Transformación modular con dbt o scripts integrados def preprocess_features(df): # Tratamos nulos de forma reproducible df['age'] = df['age'].fillna(df['age'].median()) # Codificación categórica return pd.get_dummies(df, columns=['geo'])
3. Validación y Calidad

Unit Tests para Datasets

El modelo no debe entrenar si el dato no cumple el contrato de esquema.

import great_expectations as ge # Definir expectativas de calidad df_ge = ge.from_pandas(training_df) df_ge.expect_column_values_to_not_be_null("driver_id") df_ge.expect_column_values_to_be_between("rating", 0, 5)
4. Versionado de Datos (DVC)

Git para Big Data

Vinculamos el código con el hash inmutable de los datos.

# Comando CLI simulado en bloque descriptivo $ dvc add data/raw_dataset.csv $ git add data/raw_dataset.csv.dvc .gitignore $ git commit -m "Versionado dataset v1.4 para experimento #42" $ dvc push # Envía el dataset real a S3/GCS

Error Fatal: Training-Serving Skew

Ocurre cuando la lógica de cálculo de una feature en el notebook de entrenamiento (Pandas) difiere de la lógica en la API de producción (SQL/Java). **Solución:** Implementar una Feature Store que centralice el cálculo de la feature para ambos entornos.

Health Check: Fase de Datos

Integridad

¿El 100% de las columnas cumplen con el tipo de dato esperado?

Frescura

¿La latencia de los datos en tiempo real es menor a 500ms?

Deriva (Drift)

¿La distribución estadística de las features ha cambiado > 10%?

Checklist MLOps: Gestión de Datos

Inmutabilidad Garantizada

¿Se ha prohibido la sobreescritura de archivos de datos existentes?

Esquema Validado

¿El pipeline de datos falla si se detecta una columna nueva o faltante?

Snapshotting de Experimento

¿Cada corrida de MLflow está vinculada a un hash de datos específico?

Anonimización (PII)

¿Se han eliminado o cifrado datos sensibles antes de entrar al Feature Store?

Monitoreo de Nulls

¿Existe una alerta automática si el porcentaje de nulos sube del histórico?

Lineage End-to-End

¿Podemos rastrear el dato desde el Dashboard final hasta la DB de origen?

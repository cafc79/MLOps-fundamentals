# Serving Industrial

MLOps Pillar #4: El Momento de
la Verdad

### Definición

Es la fase donde el artefacto del modelo se transforma en un servicio productivo. No solo
implica "exponer una API", sino garantizar **alta disponibilidad, baja latencia y
escalabilidad elástica** frente a la demanda fluctuante del negocio.

#### Elemento Distintivo

"Un modelo en Serving es software vivo. A diferencia de una app tradicional, el Serving debe
gestionar el **vínculo inquebrantable** entre la versión del código del servidor y
la versión de los pesos del modelo."

## Conceptos Pilares

- **Inferencia de Baja Latencia:** Optimización técnica para
  que el modelo responda en milisegundos (mínimo P99).
- **Infraestructura Inmutable:** Uso de contenedores para
  asegurar que el entorno de predicción sea idéntico al de entrenamiento.
- **Traffic Splitting:** Capacidad de redirigir porcentajes de
  usuarios a diferentes versiones del modelo sin caída del servicio.

## Análisis de Valor

#### Ventajas

- • Escalabilidad automática ante picos de demanda.
- • Despliegue de modelos sin riesgo (Zero-Downtime).
- • Optimización de costos mediante "Scale to Zero".

#### Desventajas

- • Alta complejidad en orquestación (K8s/Istio).
- • Latencia introducida por capas de red y contenedores.
- • Costo operativo de mantener clústeres activos 24/7.

## Pipeline de Inferencia Industrial

1. Inferencia en Tiempo Real (FastAPI)

### Definición del Endpoint

El modelo se expone mediante una interfaz RESTful que valida los
datos de entrada (Pydantic).

from fastapi import FastAPI
from pydantic import BaseModel
import joblib
app = FastAPI()
model = joblib.load("model\_v4.pkl")
class InputData(BaseModel):
feature\_1: float
feature\_2: float
@app.post("/predict")
def predict(data: InputData):
prediction = model.predict([[data.feature\_1, data.feature\_2]])
return {"prediction": float(prediction[0])}

3. Canary & A/B Testing

### Estrategias de Reducción de Riesgo

Dividimos el tráfico para validar el nuevo modelo (Challenger)
contra el actual (Champion).

#### Canary Deployment

Lanzar la V2 al 5% de usuarios. Si las métricas de salud
técnica son estables, escalar al 100%.

#### A/B Testing

Comparar dos algoritmos distintos en producción para ver
cuál genera mejor conversión de negocio.

## Gatekeeper: Validación Cruzada (K-Fold)

### Definición Industrial

La Validación Cruzada divide los datos en **K particiones**. El modelo se
entrena y valida K veces, asegurando que su capacidad predictiva sea consistente en todo
el espectro de datos y no dependa de un "golpe de suerte" aleatorio.

Por qué en Serving: Es el paso final del
pipeline automatizado (CT) antes de que el CI/CD autorice el despliegue de un
contenedor.

### Pros & Contras

#### Ventajas

Estimación de error imparcial. Máximo
aprovechamiento de datos limitados. Robustez garantizada.

#### Desventajas

Coste computacional lineal ($O(K)$).
Complejidad en series temporales (requiere orden cronológico).

## Higiene de la Infraestructura de Serving

#### Error: Cold Starts en Serverless

Desplegar modelos pesados (ej. Deep Learning) en funciones Lambda/Cloud Run.
**Impacto:** Los primeros usuarios esperan 30 segundos mientras el contenedor carga
los pesos. **Solución:** Usar "Warm Instances" o despliegues persistentes en K8s.

#### Práctica: Liveness & Readiness Probes

Configurar Kubernetes para que no envíe tráfico al modelo hasta que los pesos estén 100%
cargados en memoria RAM.

## Checklist MLOps: Serving y Despliegue

##### Carga Progresiva (Canary) Configurada

¿Tenemos la capacidad de revertir automáticamente si el error rate
sube al 1%?

##### Esquema de API Versionado

¿El endpoint maneja versiones (ej. /v1/predict) para evitar romper
apps clientes?

##### Cuantización / Optimización de Grafo

¿Se ha reducido el peso del modelo (ONNX/TFLite) para optimizar la
RAM del servidor?

##### Validación de Esquema en Inferencia

¿La API rechaza peticiones con datos nulos o tipos incorrectos antes
de tocar el modelo?

##### Seguridad y Rate Limiting

¿Se han implementado API Keys y cuotas para evitar ataques de
denegación de servicio?

##### Linaje de Inferencia (Logs)

¿Se guardan las predicciones (request/response) para el futuro
análisis de Data Drift?

# Entrenamiento Continuo (CT) en MLOps

## MLOps Nivel 2: La Evolución del Modelo

### Definición

Es la capacidad de un ecosistema MLOps para re-entrenar, validar y registrar automáticamente
nuevos modelos en respuesta a disparadores de rendimiento o datos. El CT asegura que la
inteligencia del sistema no sea estática, sino que aprenda de la \*\*"Verdad de Campo" (Ground
Truth)\*\* capturada en producción.

#### El Valor del CT

"Mientras el CI/CD automatiza el software, el CT automatiza la ciencia. Es el motor que combate
el **Model Decay** y el **Concept Drift**, manteniendo el ROI del
modelo intacto frente a un mundo cambiante."

## Detalle Técnico de la Fase CT

1. Triggers (Disparadores)

### La Señal de Activación

Un pipeline de CT no corre 24/7. Se activa bajo condiciones
específicas validadas estadísticamente.

#### Por Calendario

Cada lunes 02:00 AM para capturar la tendencia de la
semana.

#### Por Drift

Detectado en Fase 5: La distribución de datos cambió >
15%.

#### Por Performance

El F1-Score real en producción cayó por debajo del 0.85.

# Lógica de Trigger en el Orquestador
def check\_retrain\_condition(drift\_score, performance\_metric):
if drift\_score > 0.2 or performance\_metric < 0.80:
trigger\_pipeline(project\_id="CT\_Sales\_Forecast")

3. Evaluación Comparativa (Champion vs Challenger)

### Gatekeeper de Calidad

Nunca reemplazamos el modelo actual automáticamente. El nuevo
modelo debe demostrar superioridad.

# Evaluación Champion (Producción) vs Challenger (Nuevo)
def evaluate\_and\_promote(new\_model,
current\_model, test\_data):
challenger\_perf = eval(new\_model, test\_data)
champion\_perf = eval(current\_model, test\_data)
# Promoción solo si mejora > epsilon
if challenger\_perf > (champion\_perf + 0.02):
promote\_to\_production(new\_model)
else:
abort\_deployment(reason="No significant
improvement")

## Validación Cruzada (K-Fold): El Filtro CT

### Definición Industrial

En el Entrenamiento Continuo, no confiamos en un solo split. La **Validación
Cruzada** divide los datos nuevos en $K$ bloques, entrenando y validando $K$
veces. Esto asegura que el "retrain" sea robusto a fluctuaciones estacionales en los
datos frescos.

from sklearn.model\_selection import cross\_val\_score
scores = cross\_val\_score(model, X\_new, y\_new, cv=5)
# ALERTA: Si std(scores) es alta, el nuevo dato es ruidoso. No
desplegar.

#### Ventajas

- • Máxima estabilidad estadística.
- • Detecta Overfitting local.
- • Evita el sesgo de selección.

#### Desventajas

- • Coste computacional $K \times$.
- • Lenta para modelos pesados.
- • Compleja en Series Temporales.

Diferenciador: "En CT, la validación
cruzada actúa como el seguro contra incendios; previene que un lote de datos corruptos
re-entrenen el modelo y rompan el negocio."

## Diagnóstico de Salud: CT Phase

#### Error: Feedback Loop Bias

Entrenar el modelo solo con los datos que "pasaron" el filtro del modelo anterior.
**Consecuencia:** El modelo se vuelve cada vez más ciego a los casos que ya
rechaza. **Solución:** Incluir muestras aleatorias de exploración en el
entrenamiento.

#### Práctica: Shadow Retraining

Ejecutar el re-entrenamiento en un entorno paralelo "espejo" y comparar predicciones en tiempo
real antes de mover al Champion al Registry oficial.
